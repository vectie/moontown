# Cross-Book experiment and peer-challenge plan

## Intent and source grounding

Advance the prior one-contribution salon selection into a connected loop:
retained outputs → operator-authored combined hypothesis → independently assigned
peer challenges → fresh saved/prepared/explicitly run collaboration → normal
named-owner result review and optional Book outcome intake.

The authored MoonTown PRD (30 September 2026, version 1) identifies cross-Book
synthesis in MOONTOWN-UC03/B03 and contradiction review in MOONTOWN-F02. Input
snapshots must be attributable, unavailable Books must remain named gaps, and
Town cannot accept Book truth. This is a bounded local implementation toward
those outcomes, not qualification of the versioned synthesis operation.
`DOCUMENT_PROTOCOL_PHILOSOPHY.md` calls for exchanged new ideas/questions to
return to source Books. The current research handoff fixture's quality rules
require two-Book bridges and an experiment falsifier.

## Document protocol fit

- Source of truth: immutable existing collaboration revisions and retained work;
  the new proposal is serialized in the new saved draft question.
- Protocol owner: existing Collaboration authoring service, with one explicit
  oneoff-followup operation. No parallel scheduler or runner.
- Agent roles: the successful source Books independently challenge the shared
  proposal through the existing explicitly launched one-off runtime.
- Ledgers: the original source/result/review histories remain unchanged; the
  new ID gets its own saved revisions and run/result/review records.
- Review gate: a new draft is unrun. No inherited result approval. Book keeps
  its own acceptance gates after the normal result review and submission path.
- Projection: the existing Rabbita Collaboration work panel composes the
  hypothesis, exact excerpts, source connections, per-Book challenges,
  experiment, falsifier, dissent and assumptions.

## Acceptance and recovery

- At least two completed retained contributions, each linked to its original
  participant and sources; failed Books remain named and never become evidence.
- Each excerpt must be an exact substring of its retained output; browser-sent
  source/run/output identity cannot override the server-derived references.
- Question/result changes invalidate form notes; interrupted requests preserve
  them. A same-ID exact retry uses the existing save guard. A conflicting ID or
  changed current source blocks rather than overwriting.
- New input snapshots explicitly recapture current original Book paths; prior
  output excerpts and prior source identities remain distinct historical data.
- Source preparation, run launch, result review and Book acceptance remain
  separate existing actions. No autonomous emergence, saved time or real
  provider quality claim is made.
