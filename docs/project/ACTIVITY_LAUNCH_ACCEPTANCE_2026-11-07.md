## 与已有概念的连接

批准对象是具体申请版本及资源范围，沿用统一身份、Challenge、creative_contest 和
活动级权限。落地书生成独立活动配置与状态，不让主办填写集群地址、服务凭据或工作流节点。
主办管理自己的活动、审核投稿、暂停恢复并在授权范围内处理发布与结果。

每个活动通过原生 Book CLI 导入 `banxing-coffee-curator` 1.2.0 运行模板，
保存已批准工作簿、版本和摘要，配置 `coffee_curator` 草案 profile。真实准备收据已经
通过活动创建回调的完整校验并进入 published 状态的针对测试。
`agent_state` 始终是 `configured-not-started`；没有自动启动 MoonClaw 或语言模型任务。
图像生成沿用已验收的固定 Z-Image-Turbo/ComfyUI 路由及活动额度。

完整品牌素材仍在 1.1.0 来源档案及现有共享素材页面。运行模板不逐活动复制视频和全部图片，
也不把档案中的 `raw/`、`portable/` 路径伪装成新活动本地已有文件。
原生导入从原档案的 **869,216 KiB 峰值 RSS / 9.55 秒**，降至运行模板的
**20,228 KiB / 1.50 秒**。准备只发生在活动创建时；不在每次访问或出图时重复导入。
详见 [桥接说明](ACTIVITY_CURATION_BRIDGE.md)。
