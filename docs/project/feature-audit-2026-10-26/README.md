# MoonTown 功能入口与完成度总览

审计日期：2026-10-26。当前产品已有大量本地工具、执行适配器和空间表达，但公开小镇、私有工作区、开发样例和专业命令尚未形成同一套用户旅程。应优先修正真实性和无效入口，再合并重复流程；保留现有画风、完整 3D 模型及后端权限校验。

后续实施：[第一轮优化与验收记录](implementation.md)。下文保留实施前的审计基线；当前改动和验证范围以上述记录为准。

本清单由六条链路审计汇总，覆盖当前 `main` 工作区，包括此前未提交的改动。六份明细共 **115 行，排除 2 个跨链重复后为 113 个功能及验收盘点项**。这不是“113 个已经上线的功能”，也不是 113 个应当显示给用户的按钮。上轮“约 60 项”是更粗的能力分组估算；本次把不同入口环境和验收阶段展开，因此不能直接比较。

统计规则：

- 同一能力的首页按钮、建筑入口、运营快捷入口只算一次。多个导出格式、四座地标、机房五级模型、8 种通信模式不各自膨胀计数。
- R01 是关注任务创建，K11 补充同一能力的本地材料监测；汇总保留 K11 的详细边界，R01 为交叉索引。
- R02 是 PDF 创建请求，K19 包含同一创建能力及模板安装；汇总以 K19 为准。K20 是后续 PDF 证据执行阶段，单列是为了防止“建册成功＝研究成功”。
- Civic 的 11 个注册模块只作分组，不再加到 C01–C27 上。Town Shell/Vitality 的地图和运行能力已计入 S/O 链。
- 不同权威系统不能仅因名字相同去掉一条：本地建筑 fixture、地图布局、真实 Marketplace listing；协作结果提交、Supervisor 的 Bookkeeper submission，分别保留验收对象。
- 不统计内部 helper、包数量、校验规则、测试数量和代码行数。LunaNexa、MoonDesk、MoonBook、MoonClaw、Bunnia 的全部产品能力不在本清单，只记录 MoonTown 暴露的集成边界。

## 优先发现

### P0 修正真假与无效入口

| 发现 | 影响 | 建议动作与验收标准 |
| --- | --- | --- |
| 公共扩展工具 404 后仍展开所有表单 | 用户看到很多工具，却无法完成任何动作，且误以为自己填错了字段 | 按宿主能力和授权判断是否可用。未连接时只显示简短状态与真实可达的工作区入口，不挂空表单；已连接再加载对应工具。不能仅修相对 URL 就认为公共只读 API 已开放。[K12–K17](materials.md) |
| 政策置信度来自任务阶段常数、人才 Verified/匹配率为样例、机器人信号由 tick 生成 | 制造“业务已验证/实时运行”的错觉；藏入 Advanced 仍然是错误含义 | 没有测量定义和证据就删除百分比/Verified/live 标签，或局部明确“示例”；用来源、更新时间、待核实状态代替。[Civic 真实性证据](civic.md) |
| 登录、算力目录、执行授权、任务落机常被误读成同一件事 | 用户会以为看到机器就可以执行、看到连线就知道任务在哪台机器 | 分别显示当前账户/资源范围、工作区就绪、运行状态与已验证绑定；没有证据保留未接入，不能猜位置。[A01–A11](accounts.md)、[SU01–SU03](spatial.md) |
| 本地 fixture 与正式接口名称相似 | 容易把示例搜索/审阅/建筑发布当作线上能力 | 普通导航只使用当前部署支持的正式能力；fixture 放开发预览并显式标识，不混合真实历史。[O15–O20](operations.md) |

### P1 合并用户旅程而不是删除能力

| 当前分散或重复 | 建议归并 | 不可合并掉的边界 |
| --- | --- | --- |
| 小镇“发起工作”和 Operations 请求台 | 一个创建器、同源快捷入口 | 管理员与普通用户的可执行范围 |
| 新协作、复用、旧成果再研究、假设组合、声明质疑 | 「新建工作 / 继续研究」，选择来源和意图后共用编辑器 | 草稿、真实执行、人工审核、知识接受是不同阶段；R12 不等于通用实验执行 |
| Pack 手选来源、相同材料、词汇发现、历史变化、跨 Pack 问题五套并排表单 | 「选择资料→写问题→提交」，按需切换找资料方式 | Pack mailbox 只收候选；Book collaboration 可以执行，两种目的不能暗中替换 |
| 历史成果库、成果搜索/比较、建筑研究成果、导入成果抽屉 | 常用「成果」入口，按来源/类型切换；成果搜索和比较目前 CLI-only，需接 UI | 原始文件、领域观察、已审核结果、已接受知识的来源与真实性不同 |
| 审核、任务通知、Marketplace 申请、Orderlist、运行失败 | 同一个「待我处理」列表，再进入各自任务详情 | 保留各协议的权限和验收状态，不能混入 fixture inbox |
| Contest 地图卡、Quests 模拟 readiness、完整 Hackathon 工作台 | 建筑与任务卡显示真实赛事摘要并深链到一个赛事空间 | 合成评测、真实 benchmark、临时/最终排名必须分开 |
| Social Square、Talent Avenue、Marketplace Discover | 「发现」的不同类别：人、项目、Agent、建筑 | 示例人物不能成为正式人才认证；推荐不能无依据打概率分 |
| PlanBook、自检、repair、editor pipeline、Native Work | 管理员/开发者「建设计划」详情：计划→执行→验证→结果 | 执行器回执不等于代码已被 owner 接受 |
| goal table、outlook、stagger、merge、Code schedule | 「自动任务」管理里的编辑、影响预览和冲突处理 | 手动 baseline 对比不是周期监测；研究与 Code 任务授权不同 |
| 生产空间报告、独立 Studio 规划报告 | 同一报告数据契约和导出组件，保留普通摘要与专业视图 | 实测快照和设计估算不混成一个实时“统计” |
| 本地账户管理与统一平台账户 | 正式环境仅保留统一账户入口，旧账户只供本地兼容 | 不按邮件/显示名迁移授权；不会因 UI 合并就获得新的权限 |
| 多处 JSON/CSV/Markdown/原始文件按钮 | 当前对象的一个「导出」菜单 | 完整原文和筛选结果要清楚区分；共享对象与接收人需确认 |

不是所有多入口都应删除。地图建筑、工作列表、快捷按钮可以进入同一对象，只要共用状态与命名；问题是重复的表单、数据来源和互不相认的状态。

### 已经统一的部分不要重复重建

- 室内和地下都使用 `render_spatial_stage` 与同一套 Town-owned Three.js viewport。旧室内 Canvas/地下示意不是当前第二套生产方案。[当前实现与回归约束](spatial.md)
- 独立 G3/数据中心 Studio 是设计审阅工具，已主要位于高级入口。保留完整模型；统一报告与对象语义比再删一套查看器有价值。
- Map Lab 旧独立 ML 启动器已经隐藏，当前高级入口与快捷键不是两个功能。
- 运行 Agent 和地标 walker 的导航仍是两条不同用途链路。可以共用底层路径接口，但演示过桥不能冒充真实任务的跨楼执行。

## 哪些放 Advanced

Advanced 应是当前任务的低频选项，不是把所有复杂内容塞进去的新菜单。名称统一为「高级」，少量公认动作可用同一套线性图标；领域动作保留短文字，图标提供可访问名称和必要提示。

| 层级 | 放什么 | 不放什么 |
| --- | --- | --- |
| 默认主流程 | 当前任务/对象、真实状态、结果、数据新鲜度、下一步；用户必须选择的资料/目标/权限范围 | 原始 schema、hash、tick、路径、运行器内部名 |
| 当前任务的高级选项 | 非必要覆盖参数、来源精确路径、关键词 ANY/ALL、baseline 文件、复杂筛选、规划假设、光照/白模、原始记录/导出 | 结果本身、阻止继续的错误、是否演示、谁能访问、执行影响 |
| 管理员界面 | 全局健康、系统设置、调度策略、成员/审核管理；必须先有真实管理员权限 | 普通用户可展开的“管理员 Advanced”假门禁 |
| 开发者诊断 | Map Lab、PID/心跳、outbox claim/reconcile、强制 sync、源码修复/部署、内部身份和协议调试 | 普通用户首页、公共演示的可操作入口 |
| 演示/设计模式 | 假设容量、原理动画、地标步行预览、固定人物及开发 fixture | 真实指标、已认证人物、真实任务的默认状态来源 |

**需要上提，而不是继续隐藏：** 历史成果库 R07、待审核 R05/R19、授权机器 A03，以及当前问题的可行动解释。审核人显示可理解身份，不要求普通用户复制 reviewer ID。无权限、未连接、执行结果未知、来源不足和需要确认的分享范围保持直接可见。

界面收纳不减少后端授权、隔离、版本检查、幂等和审计；系统自动做检查，只把用户需要理解或改变的结论呈现出来。[GOV.UK 的 Details 使用边界](https://design-system.service.gov.uk/components/details/)明确不应隐藏多数用户需要的信息；[W3C 表单通知指南](https://www.w3.org/WAI/tutorials/forms/notifications/)要求反馈清楚，并说明如何解决错误。此处应用于本项目，不是另起一套视觉风格。

## 建议保留的五个主入口

| 主入口 | 主要回答 | 归入的能力 |
| --- | --- | --- |
| 小镇 | 我在哪里，可以去哪里？ | 地图、建筑、室内/地下、地标；布局编辑单独进入 |
| 工作 | 我要做什么、现在进展如何、什么需要我处理？ | 新建/继续研究、我的 Agent、自动任务、任务详情、审核与异常 |
| 成果 | 我得到了什么，依据是什么？ | 已有成果、材料、比较、继续研究、导出；来源类型明确 |
| 算力 | 我能用什么，当前状态是什么？ | 当前账户资源、机器/模型服务、空间视图、报告；规划与实测分开 |
| 账户 | 我是谁，属于哪里，有哪些授权？ | 唯一登录、组织、方案/权限、工作区、退出 |

这是建议的目标导航，**本轮没有实现新菜单**。公共游客默认只需小镇、演示算力、登录；进入真实工作环境后再出现其有权限使用的工作/成果。管理员另有角色限定管理入口，不要求所有人理解运行器和底层产品分工。

## 执行顺序和验收要求

1. **真实性与可达性**：处理公共 Pack 404 和假指标；每个展示卡可回答“真实、设计还是样例”；不可用入口只有一个明确下一步，不出现整屏禁用表单。
2. **工作与成果**：共用任务创建器；历史成果库移出 Advanced；统一“待我处理”。不改变接受知识和执行授权的所有者。
3. **专业模式归位**：布局编辑、Studio、自动任务高级参数、构建/修复、诊断按角色和场景收纳；保留模型与画风。
4. **真实链路补齐**：A/B/admin 隔离、私有工作区、账户 MoonGate 路由；再做真实 Run→机器、物理位置和遥测绑定。不能先画一条成功连线当成完成。
5. **按部署验证**：同一条功能至少分别记录本地/CLI、私有部署、公共入口的结果。测试 passing、演示可操作、真实用户端到端成功分别保留证据，不互相升级。

本轮未实施上述修改，未提交或推送，保持 `main`；新增审计文档和项目文档索引，不改产品代码、画风、模型、账户或线上状态。

## 文档冲突与维护

目前旧文档中有“室内/地下未整合”“默认 ACP”“HTTPS 尚未部署”等历史阶段描述，不能覆盖最新实现或 10/23 的 8443 部署；同样，最新公共上线不能替代老链路缺失的真实业务验收。详细纠偏在各链路文末。

后续新增能力时复用既有编号和入口归属，不按按钮累加。状态升级需要更新同一行的环境、证据日期、真实数据/权限范围、剩余缺口；接口名字或测试样例本身不足以升级。建议每次发布检查本清单的入口与状态，不再维护无法验证的全局完成百分比。
