# Run an idea salon over captured Book contributions

The Collaboration screen now supports a structured, operator-authored comparison
of the actual one-off outputs. It reuses the current source capture, participant
execution, named-owner result review, and Book outcome receiver. This is the
missing selection interaction; it adds no alternative runner or civic installer.

## Journey

1. In Collaboration choose at least two existing Books, exact source paths, a
   question, assignments, a reviewer, and an independently owned objection.
   Save and prepare the revision using the existing composer.
2. Run participants once through the configured one-off runtime, then collect
   their results. With no configured runtime, this remains blocked; opening the
   salon does not manufacture contributions.
3. Once all participants are terminal and at least two completed contributions
   have retained outputs, choose **Compare ideas from these Books**. Failed Books
   stay visible and cannot be selected or counted as agreement.
4. State one comparison criterion. Read each returned output, assess every
   completed contribution against that criterion, and choose one for Book review.
   Record why, alternatives not chosen, dissent, and unresolved assumptions. The
   original authored objection is shown and retained independently of these notes.
5. Complete the existing named-owner result decisions. Their approval covers the
   accurate result account, not approval of the newly authored choice. Choose a
   destination Book, supply the existing outcome interpretation and Three-Gap
   statements, then choose **Send selected salon outcome to chosen Book**.
6. The existing product-import path sends one exact source/result/review dossier
   with the structured selection inside its interpretation artifact. Book's
   summary identifies the chosen Book contribution. Book still owns deliverable
   and Three-Gap acceptance. Use the existing Book disposition/readback action.

## What is retained and checked

- The same saved question, revision, result digest, and original objection
- Every successful contribution's comparison, real proposal/run/output identity,
  output digest, and captured input snapshots; other candidates stay as alternatives
- Explicit failed Book IDs and the unchanged result dossier with failure details
- Criterion, selection rationale, alternatives, dissent, and unresolved assumptions
- `comparison_kind: operator-authored comparison of retained outputs` and
  `genuine_emergence_verified: false`

The server derives all source/output references from retained work, never from
browser fields. Unknown/failed selections, an omitted candidate assessment,
missing dissent/alternatives/assumptions, and stale result-bound notes block the
Book package. Existing ordinary outcome submissions remain supported.

Comparison notes are form state until submission. An interrupted request or a
same-result refresh preserves them. Changing a question, source, participant,
reopening a saved revision, or collecting a different result clears them. The
explicit discard button only clears the comparison fields. Submitted selections
remain in the existing immutable outcome package, including on idempotent retry.

## Evidence and authority limits

This is an operator comparison, not a generated multi-agent debate or an
execution of `evaluate_autonomous_civic_round`. That separate emergence protocol
requires independently supplied critique/ranking/review stages; this UI does not
fabricate them. Deterministic fixture contributions remain fixture rehearsals.
Configured runtime output is retained as returned; no genuine emergence, live
provider quality, company commitment, or automatic Book acceptance is claimed.

No new service, provider, schedule, permission, or recurring goal is installed.
The destination in this slice is the existing Book workflow. MoonProj delivery
is not implemented or implied.
